“Codex 首字要等 20 秒，而且明显变笨了”，这是国内社区里最常见的抱怨之一。它把两个不同的现象绑在一起：**慢**是一个可测量的事实，**笨**是一个主观感受。二者可能同源，也可能完全无关。这篇文章不承诺“怎么绕过风控”，只做一件事：给你一条从近到远的排查顺序，让你能判断问题出在自己这一端、账号这一端，还是服务端。

文中提到的时间、比例均为社区普遍观察，仅作参考。

## 一、先把“慢”和“笨”拆开测

排查之前先做两个最简单的对照：

```bash
# 1. 新开一个干净会话，问一个与项目无关的小问题
codex "用一句话解释什么是幂等"

# 2. 在 CLI 里查看当前用量窗口
/status
```

- 如果干净会话的首字延迟也很长 → 问题不在你的项目上下文，往网络、账号、服务端方向查。
- 如果干净会话很快、项目会话很慢 → 问题多半是上下文膨胀或工具调用过多，往第三节看。
- `/status` 显示短窗口剩余很少 → 你正在被软限速，这是最常见也最容易被误判为“降智”的情况。

## 二、限流：额度快用完时的“软降速”

Codex 的额度是双窗口滚动制（约 5 小时 + 约 7 天），机制细节见 [Codex 额度机制详解](/blog/cn-codex-quota-explained/)。很多人不知道的是：**额度接近上限时，服务端可能先降速再拒绝**，而不是直接报错。表现就是首字延迟拉长、长任务中途排队。

判断依据：

| 现象 | 更像限流 | 更像其他原因 |
|---|---|---|
| 首字慢但输出流畅 | ✓ | |
| 全程断断续续 | | 网络 / 代理 |
| `/status` 短窗口低于 20% | ✓ | |
| 换成 API Key 登录立刻正常 | ✓ | |
| 换网络后立刻正常 | | 网络 / 代理 |

限流的解法只有等窗口刷新、加购额度或切 API Key。它和“账号被盯上”没有关系，不需要换号。

## 三、上下文膨胀：最常被忽视的“降智”来源

一个会话跑久了，上下文里堆满了历史工具输出、失败的尝试和长文件内容。模型在这样的上下文里回答质量下降是正常现象，不是被降级了。典型信号：

- 同一个问题在新会话里回答得明显更好。
- 模型开始引用早已被你改掉的旧代码。
- 单条消息的额度消耗越来越大（`/status` 掉得比平时快）。

处理方式很朴素：**阶段性新开会话**，把当前进度写进 `AGENTS.md` 或一个 handoff 文件再续。长任务怎么交接站内 [Codex 长任务交接](/blog/codex-long-task-handoff/) 讲过。另外，思考等级调高不一定更聪明，反而会放大上下文膨胀的代价，见 [Codex 思考等级与实际表现的权衡](/blog/codex-thinking-level-tradeoff/)。

## 四、网络与代理：国内用户“首字 20 秒”的第一嫌疑

国内直连不可用，绝大多数人都通过代理访问。代理带来的延迟有几种典型模式：

1. **握手慢**：每次请求都要重新建立 TLS 连接，首字延迟大，但输出开始后很流畅。多见于代理规则把 API 域名走了慢线路。
2. **流式被缓冲**：某些代理软件或中间层会把 SSE 流攒够一段再发，表现为“等很久突然一大段”。
3. **节点被服务端识别为高风险出口**：同一个出口 IP 背后有大量账号，服务端会对该出口的请求更保守。这种情况换一个干净节点通常立刻改善。

自查方法：在同一台机器上，用浏览器打开 ChatGPT 网页发一条消息，对比首字时间。网页快、CLI 慢，先检查 CLI 的代理配置是否走了不同规则。国内配置要点见 [Codex CLI 国内配置与使用指南](/blog/codex-cli-cn-setup/)。

## 五、风控：什么情况下账号本身会被“区别对待”

这一节只讲判断边界，不讲规避方法。服务端对账号的风险评估是不公开的，但社区普遍观察到几类会触发更严格处理的情形：

- **短时间内多地登录**：同一账号在多个国家的出口 IP 上同时活跃。
- **登录信息不一致**：账号地区、付款卡地区、手机号国家、IP 归属四者对不上。
- **高频并发**：同一账号同时开很多个 Codex 会话，尤其是云端任务批量提交。
- **账号来源异常**：批量注册、共享的账号本身就在风险名单里。

被风控的表现和限流不同：限流会随窗口刷新恢复；风控可能持续更久，或直接要求补充验证（比如登录时要求验证手机号，见 [Codex 登录要求验证手机号：国内用户怎么过](/blog/cn-codex-login-phone-verification/)）。

如果你的账号是自己注册、自己付款、固定一两个出口 IP 使用，正常并发，那么“被风控降智”基本可以排除，问题大概率在前面三节。

## 六、号池共享：几乎所有“无解的慢”都来自这里

国内很多“便宜 Codex 账号”实际是号池：一个账号或一批账号同时给很多人用。从机制上看它必然又慢又不稳：

- 短窗口额度是按账号算的，几十个人共用一份，任何时候都可能处在限流边缘。
- 多地同时登录正是上一节说的风控触发条件。
- 服务商为了续命会频繁换号，你的会话、设置、`AGENTS.md` 指向的上下文随时失效。
- 你的代码仓库内容会经过第三方账号，这是安全问题，不只是体验问题。

判断自己是不是在号池里很简单：账号邮箱不是你的、或者“登录后不要改密码”、或者提示“不要同时超过 N 个会话”。如果是，慢和笨都不是排查能解决的，换成自己的订阅是唯一出路。共享账号的风险站内 [ChatGPT 共享账号的真实风险与替代方案](/blog/cn-chatgpt-shared-account-risk/) 有更完整的说明。

## 七、一份可直接照做的排查清单

按顺序做，命中一条就停：

1. 新开干净会话对照 → 快了就是上下文问题，新开会话并做交接。
2. `/status` 看窗口 → 低于 20% 就是限流，等刷新或加购。
3. 浏览器网页对照首字 → 网页快就是 CLI 代理规则问题，改代理配置。
4. 换一个干净代理节点 → 好转说明出口 IP 被保守处理。
5. 检查登录方式 → 若是号池账号，停止排查，换自己的订阅。
6. 以上都排除，账号地区 / 付款 / 手机号 / IP 四者核对一致 → 仍异常，等待服务端恢复或联系官方支持。

这条清单的价值在于：**前四步都不需要碰账号**，能解决绝大多数问题；只有第五步会指向“账号本身有问题”。
