用 ChatGPT、Claude 这类工具久了，总会遇到它一本正经说错话的情况——编一个不存在的网址、算错一道简单数学题、把两个人物的事迹张冠李戴。很多新手第一反应是"这个 AI 是不是很差"，其实这背后有几个结构性原因，理解了这些原因，你会更清楚什么时候该信任 AI 的回答、什么时候必须自己核实。

## 一、AI 不是在"查资料"，而是在"猜下一个字"

这是理解一切错误的起点：大语言模型的工作原理不是从数据库里检索答案，而是根据前面的文字，一个字一个字地预测"接下来最可能出现的内容是什么"。它在训练过程中见过海量文本，学会了语言的统计规律和大量知识，但**回答问题的机制始终是"生成看起来合理的文字"，不是"查证事实后如实转述"**。

这就是为什么它会一本正经地编造一个不存在的引用、网址或人名——这些内容在统计上"看起来像"真实存在的东西，模型没有一个内置的"事实核查"环节去验证自己编的东西是不是真的存在。这种现象业内叫"幻觉"（hallucination），是所有大语言模型都存在的固有特性，不是某个产品做得差。

## 二、知识有截止日期，之后发生的事它不知道

每个模型都是用截止到某个时间点的数据训练出来的，之后发生的事件、发布的产品、更新的政策，模型本身并不知道。如果你问一个模型训练截止日期之后才发生的事，它有两种反应：一是诚实地说"我不知道这之后的信息"，二是根据训练数据里的规律硬猜一个答案——第二种情况就是错误的重要来源之一。

判断是否需要联网搜索能力来补足这个短板，是新手最容易忽略的一步：纯聊天模型和带联网搜索的产品（比如网页版开启了搜索功能）给出的时效性答案质量完全不同，问最新信息之前先确认你用的版本是否具备联网能力。

## 三、你的问题本身不够清楚，AI 只能猜你的意思

很多"答错"其实是"答非所问"——用户的提问本身有歧义，AI 按照最常见的理解去回答，但恰好不是用户想要的那个意思。比如问"帮我优化一下这段代码"，AI 不知道你是要优化性能、优化可读性还是优化安全性，它会挑一个它认为最常见的方向去做，如果和你的真实需求不一致，看起来就像是"AI 理解错了"。

解决办法不是怪 AI，而是像和一个不了解背景的新同事说话一样，主动补充关键信息：目标是什么、有什么限制、参考什么标准。写系统提示词也能帮上忙，具体方法见 [System Prompt 新手入门指南](/blog/system-prompt-for-beginners/)。

## 四、聊得太久，AI 会"忘记"前面说过的话

每个模型能一次处理的文字量是有上限的，这个上限叫"上下文窗口"，超过这个上限，最早的内容会被截断或者被模型"注意力"淡化，导致它给出的回答和你之前提供的信息对不上——这不是 AI 在瞎说，而是它已经"看不到"那部分内容了。上下文窗口的具体概念和限制可以参考 [上下文窗口新手指南](/blog/context-window-for-beginners/)。

实践中的应对方法很简单：对话变得很长之后，如果发现 AI 的回答开始和之前的设定矛盾，主动重新提供一次关键背景信息，而不是假设它还记得你三十轮对话之前说过的话。

## 五、参数设置会放大或抑制"胡说"的倾向

多数 AI 产品和 API 都有一个叫 `temperature` 的参数，控制回答的"发散程度"。这个值调得越高，回答越有创意也越容易天马行空、偏离事实；调得越低，回答越保守、越贴近训练数据里最常见的说法，但也可能显得死板。做需要严谨事实的任务（比如查数据、写代码）时用低温度，做需要创意的任务（比如写文案、头脑风暴）时用高温度，具体设置方法见 [Temperature 与 Top P 新手指南](/blog/temperature-top-p-for-beginners/)。多数网页版聊天产品把这个参数固定死了，用户看不到也调不了，这也是为什么同一个模型在网页版和 API 里表现出来的"靠谱程度"会有差异。

## 六、数学计算和精确计数是模型的天生弱项

大语言模型本质上是在处理语言规律，不是在做数值运算。你让它算一道复杂的多位数乘法，或者数一段文字里某个字出现了几次，出错概率远高于一般人的直觉预期——因为它是"用语言模型的方式生成看起来像正确答案的数字"，而不是真的在心里做加减乘除。涉及精确计算的任务，更可靠的做法是让 AI 生成代码去跑（比如写一段 Python 代码做计算），而不是直接要它口算出结果。

## 七、遇到疑似错误的答案，怎么快速自查

按下面的顺序检查，通常能很快判断这次错误属于哪一类，也知道该怎么应对：

```
1. 涉及具体网址/引用/人名 → 优先怀疑是幻觉，去搜索引擎交叉验证
2. 涉及近期事件/新产品 → 检查是否超出模型知识截止日期，换联网版本再问一次
3. 回答文不对题 → 反思问题是否有歧义，补充背景信息重问
4. 长对话里前后矛盾 → 重新提供一次关键背景，不要假设它还记得
5. 精确数字算错 → 换成"写代码计算"而不是"直接口算"
```

多数常见错误提示和排查方法也可以对照 [新手常见错误代码大全](/blog/common-error-codes-for-beginners/)，不过那篇讲的是 API 调用报错，和这篇讲的"回答内容本身错误"是两个不同层面的问题，别搞混。

## 八、一句话总结

AI 不是一个"知道所有正确答案的数据库"，而是一个"根据规律生成看起来合理内容"的工具。理解这一点之后，用它的方式会自然发生变化：重要决策不能只听它一面之词，事实性内容要交叉验证，模糊的问题要主动补充背景，精确计算要交给代码去跑。这样用，AI 才是真正靠谱的助手，而不是一个偶尔坑你的黑箱。
