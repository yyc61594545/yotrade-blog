如果你用过 ChatGPT、Claude 或者其他 AI 工具，大概率见过"Token"这个词——账单上按 Token 计费，接口文档里说"上下文限制 12.8 万 Token"。但 Token 到底是什么？它既不是"字"，也不是"字符"，很多新手在这里被绕晕。本文用最直白的方式讲清楚，不需要任何编程或技术背景。

## 一、先说结论：Token 是 AI 理解文字的"最小单位"

AI 模型不会像人一样一个字一个字地"认字"，它在处理文字之前，会先把你的文字**切成一小块一小块**，每一小块就是一个 Token。这个切分过程叫"分词"（Tokenization）。

打个比方：如果把一句话理解成一列火车，Token 就是组成这列火车的一节节车厢。车厢的大小不是固定的——有的车厢只装一个字，有的车厢能装一个完整的英文单词，具体怎么切，取决于模型用的"切词规则"（叫 Tokenizer）。

**关键点**：Token 不等于"字"，也不等于"字符"，它是模型自己定义的一种切分方式，人类肉眼很难直接数出来。

## 二、为什么不能直接按"字数"算，非要发明 Token

这是新手最常问的问题。答案和两个现实原因有关：

**原因一：语言之间没有统一的"字"概念。** 英文按空格分单词，中文没有空格，日文韩文的构词方式又不一样。如果 AI 要同时处理几十种语言，需要一种跨语言统一的切分方式，而不是各种语言各算各的。

**原因二：Token 数量和模型的实际计算量强相关。** AI 模型内部处理的是数字，不是文字。每个 Token 会被转换成一串数字（这个过程叫 Embedding），模型对这些数字做数学运算来"理解"和"生成"内容。计算量基本随 Token 数量增长，所以用 Token 计费，本质上是**按实际消耗的计算资源收费**，比按"字数"更贴近真实成本。

## 三、Token 和"字"之间的换算关系，大概是多少

这是一个近似值，不同模型会有差异，但可以帮你建立直觉：

| 语言 | 大致换算关系 |
|------|------------|
| 英文 | 1 个 Token ≈ 0.75 个单词（约 4 个英文字符） |
| 中文 | 1 个 Token ≈ 0.6–1 个汉字（因模型而异，波动较大） |

**中文用户要特别注意**：不同模型对中文的切分效率差异明显，同一段中文，用不同的 AI 模型计算出来的 Token 数量可能差 20%–40%。这也是为什么"同样字数的文章，换个模型算出来的调用成本不一样"的原因。想精确计算某个具体模型下的 Token 数量，可以参考更详细的 [Token 计算完整指南](/blog/token-counting-cn-guide/)（含代码工具，适合有一定技术基础的读者）。

## 四、Token 出现在你日常使用 AI 的哪些地方

**场景一：计费。** 几乎所有主流 AI 服务都是按 Token 收费，通常分"输入 Token"（你发给 AI 的内容）和"输出 Token"（AI 回复给你的内容）两种，价格往往不同——输出 Token 通常比输入 Token 贵，因为生成内容比理解内容需要更多计算。

**场景二："上下文长度限制"。** 你可能见过"这个模型支持 20 万 Token 上下文"这样的说法。这句话的意思是：模型在一次对话里能"记住"的内容总量（你说的话 + AI 回复的话 + 之前的历史对话）加起来不能超过这个 Token 数。聊天聊得越久、粘贴的文档越长，越容易触碰这个上限，触碰后模型可能会"忘记"最早的对话内容。

**场景三：为什么长文档粘贴进去会报错或者变贵。** 如果你把一篇几万字的文章整个粘贴给 AI 问问题，这篇文章会被换算成对应的 Token 数，可能一下就占用了大部分甚至超出上下文上限，也会直接体现在账单里。

## 五、一个常见误解：Token 不是"越少越好"

有些新手觉得"用更少的字表达意思，能省 Token、省钱"，这个想法只对了一半。

- 对于**输入**（你的提问），确实精简有帮助，冗余的描述会浪费 Token
- 但对于**输出**（AI 的回复），"更短"不代表"更省"——如果 AI 因为你的提问不够清晰，导致回复内容答非所问，你还得追问几轮，反而消耗更多 Token。**清晰准确的提问，往往比"字少"更省钱**

## 六、想直观感受 Token 是怎么切的，可以怎么做

不需要写代码，大部分 AI 服务商官网都提供可视化的"Tokenizer 测试工具"，输入一段文字，会直接高亮显示这段文字被切成了哪些 Token 块。用这类工具输入几句常用的中文和英文对比一下，几分钟就能建立起直观感受——比看十篇文字讲解都管用。

如果之后想深入了解不同模型的计费规则怎么和 Token 挂钩、怎么通过工程手段减少不必要的 Token 消耗，可以进一步看 [LLM Token 成本账本管理](/blog/llm-token-cost-ledger/) 和 [Prompt Token 精简技巧](/blog/llm-prompt-token-trimming-recipes/)，这两篇更适合已经在实际使用 API、想控制成本的读者。

## 七、小结

Token 是 AI 模型处理文字的最小单位，不等于字或字符；AI 按 Token 计费，本质是按计算资源消耗计费；不同语言、不同模型的 Token 换算比例不一样，中文用户尤其要留意这个差异；理解 Token 之后，再看 AI 产品的价格表和"上下文长度"参数，就不会再一头雾水了。
