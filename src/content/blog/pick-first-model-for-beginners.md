第一次要接 LLM API 的人,最常掉进的坑不是技术难度,而是选择困难症——打开任何一个模型供应商的定价页,几十个型号名字堆在一起,参数量、上下文窗口、每百万 token 价格全摆出来,新手根本判断不出该选哪个。这篇文章跳过参数表,直接按"你要做什么"给结论,先把第一个模型定下来,用起来之后再考虑要不要换。

## 一、别被参数表劝退,先问自己三个问题

选模型之前,不需要理解 MoE 架构、不需要知道训练数据截止日期,只需要回答:

1. **要处理的输入是纯文字,还是包含图片/文件?**——决定要不要多模态能力
2. **一次任务大概要处理多长的内容?**——决定要不要长上下文
3. **对回复速度要求多高?**——决定选轻量模型还是旗舰模型

想清楚这三点,基本能把几十个型号砍到两三个候选,不需要逐个对比参数。

## 二、四类常见场景,直接给结论

### 场景一:写代码 / 调试

**首选:Claude(Sonnet 系列)**。目前公开评测和开发者社区反馈里,Claude 在代码生成、理解已有代码库、遵循复杂指令方面的口碑持续领先,尤其是需要模型理解大段现有代码上下文再做修改的场景。配合 Claude Code、Cursor 这类工具体验更完整,新手直接用 Claude Code 命令行工具是最快上手的路径。

预算有限或者任务比较简单(比如生成一段独立函数、写单元测试)可以用 Claude 的轻量版本(Haiku),速度快、价格低,复杂度不高的代码任务够用。

### 场景二:写文案 / 创作类内容

**首选:GPT 系列(GPT-5 或对应的旗舰版本)**。在中文语境的文采、修辞多样性、创意发散上,GPT 系列长期是被引用最多的选择,尤其适合营销文案、故事创作这类需要"读起来有味道"而不只是信息正确的场景。

如果预算敏感,GPT 的轻量版本或者 DeepSeek 这类国产模型在中文创作上性价比也不错,差距主要体现在长文的连贯性和细腻程度上,短文案场景基本感觉不出明显差异。

### 场景三:做客服 / 问答类应用

**首选:根据成本敏感度分层**。客服场景的特点是调用量大、单次任务相对简单(主要是信息检索 + 组织语言回答),这种场景不建议无脑上最贵的旗舰模型,合理的做法是:

- 简单问答(FAQ 类、流程查询):用轻量模型(GPT-mini 系列 / Claude Haiku / DeepSeek),响应快、成本低
- 复杂问题需要推理判断(比如需要理解用户描述的具体问题再给个性化建议):升级到中档或旗舰模型

很多生产系统会做"路由"——先用轻量模型判断问题复杂度,简单的直接轻量模型回答,复杂的转旗舰模型,而不是所有请求都走同一个模型。这个思路作为新手第一版可以先不做,等跑起来之后再优化。

### 场景四:文档理解 / 长内容分析

**首选:Gemini(Pro 系列)或 Claude(带长上下文)**。需要一次性喂入大量文档(比如几十页 PDF、整个代码仓库)再让模型基于全部内容回答,这类场景对上下文窗口大小的要求是硬指标。Gemini 长期在超长上下文场景的公开评测里表现稳定,Claude 的长上下文版本在需要精细理解文档细节(而不只是找到大概位置)的任务上口碑也不错。

## 三、不确定选哪个,就先用这两个跑一跑

如果场景比较混合,判断不出来该归到哪一类,新手最稳妥的起点是:**Claude Sonnet + GPT 主力版本各跑一遍同样的任务,对比结果**。这不是浪费时间——真实任务上的效果差异,比任何评测榜单都有说服力,而且成本很低(单次调用的价格通常在几分钱到几毛钱之间,测试阶段的调用量不会产生明显费用)。

对比时注意控制变量:同样的 prompt、同样的输入内容,分别发给两个模型,对比输出质量、速度、以及价格,而不是凭"听说哪个更好"做决定。

## 四、第一次调用前要准备好的三件事

选定模型之后,真正开始写代码之前,建议先确认:

1. **API Key 怎么安全存放**——不要写进代码里,参考 [API Key 安全存放入门](/blog/api-key-safety-for-beginners/)
2. **用不用流式返回**——影响前端体验和实现复杂度,参考 [要不要用流式返回](/blog/streaming-or-not-for-beginners/)
3. **国内网络能不能直接访问**——如果访问不稳定,提前用中转服务解决,不要等上线了才发现连不上

新手常犯的错误是选完模型直接开始写业务逻辑,结果网络问题、密钥管理这些基础设施问题留到最后才处理,返工成本比一开始就规划好高得多。

## 五、换模型的成本比想象中低,先别纠结"选错了怎么办"

很多人在第一次选择上花大量时间纠结,是因为担心"选错了以后要推倒重来"。实际上如果代码里用统一的调用封装(不要把某个模型的专属参数硬编码得到处都是),换模型通常只是改一行配置——尤其是通过 API 中转服务统一管理多个供应商的情况下,同一套代码切换模型的成本几乎为零。先跑起来,用真实反馈决定要不要换,比在选型阶段过度分析更值得。
