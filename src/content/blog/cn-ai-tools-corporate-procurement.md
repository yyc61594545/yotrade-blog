国内企业（尤其是中大型公司）上 AI 工具，往往不是技术问题，而是采购流程问题。工程师测好了 Claude Code 或 GPT-4o API，但到了采购环节，IT、法务、财务三道门槛让事情陷入停滞。本文梳理一套实操流程，帮助技术团队顺利推动 AI 工具落地。

## 一、国内企业 AI 采购的特殊性

与传统 SaaS 软件采购相比，AI 工具在国内企业里面临几个额外挑战：

- **数据合规门槛更高**：《数据安全法》《个人信息保护法》要求明确数据出境路径；法务需要确认数据是否传输至境外服务器
- **付款渠道不通畅**：OpenAI、Anthropic 只接受境外信用卡，财务部门难以直接走采购单
- **预算科目模糊**：AI API 费用是"软件服务"还是"技术服务"，不同公司财务口径不同
- **"试点→推广"周期长**：大公司从 PoC 到全量往往 6–12 个月，中途工具可能已更新迭代

了解这些特殊性，才能在流程里提前准备材料，减少往返。

## 二、采购前：技术评估阶段（1–2 周）

在走采购流程之前，技术侧先完成自评，输出一份"采购申请简报"，是流程顺利推进的关键。

**评估维度参考**：

| 维度 | 评估内容 | 建议输出形式 |
|------|---------|------------|
| 功能适配 | 工具能解决哪个业务痛点，量化效率提升 | 对比表 + Demo 截图 |
| 成本估算 | 预计月/年 token 用量，折算费用 | 费用预测表 |
| 数据安全 | 什么数据会上传，是否含敏感信息 | 数据流向说明 |
| 备选方案 | 同类工具横向对比（如 Claude vs GPT-4o） | 选型矩阵 |
| 退出方案 | 如果停用，数据如何迁出 | 文字说明 |

这份简报的受众是 IT 负责人和法务，而不是技术同学——写得越少越具体越好。

## 三、合规审查：法务关怎么过

**常见法务问题清单**（提前准备好答案）：

1. **数据是否出境**
   - 如果用 OpenAI/Anthropic 直连 API，数据肯定出境，需走数据出境安全评估（对于敏感数据）
   - 国内中转服务（如 YoTradeApi）的数据流向需要服务商提供书面说明
   
2. **服务商是否有合规资质**
   - 大陆展业的 AI 服务商需要具备《互联网信息服务算法备案》
   - 境外服务商（OpenAI、Anthropic）通常无法直接满足大陆法规，法务一般要求通过国内合作方

3. **数据保留与删除**
   - 对话数据是否被用于模型训练（OpenAI 企业版默认不训练，需在合同里确认）
   - 停止服务后数据保留多久、如何删除

4. **合同签约主体**
   - 境外公司很难直接与国内公司签服务合同；通常由国内合规代理商或中转服务商出具合同

**实操建议**：准备一份"供应商信息安全问卷"（大公司 IT 部门往往有标准模板），提前填好发给供应商，拿到书面回复后再提交法务。

## 四、财务预算：怎么申报 AI 工具费用

AI API 按量计费的模式在国内财务体系里有点"另类"，建议从以下角度切入：

**按月订阅 vs 按用量**：
- 对财务部门来说，固定月费更容易做预算。如果服务商支持，优先签年度框架合同（固定总额），用完为止
- 如果只能按量计费，申请一个"AI 工具试点专项预算"，初期给 3–6 个月额度

**科目建议**：
- 小公司：计入"技术服务费"或"软件服务费"
- 大公司：IT 部门通常有"SaaS 工具"或"云服务"科目，AI API 可归入此类

**付款方式解决**：
- 国内合规中转服务商可以出具人民币发票，支持银行转账，彻底绕开境外信用卡问题
- 如果一定要直连境外服务，可通过公司外汇账户购汇，但审批链条更长

## 五、供应商评估：选型决策树

以 AI API（LLM 调用）类工具为例，企业采购的核心决策路径：

```
是否允许数据出境？
├─ 否 → 国内大模型（通义千问、文心一言、混元）或私有化部署
└─ 是 → 数据敏感级别
         ├─ 高（含 PII / 商业机密）→ 需要 DPA 协议，优先企业版
         └─ 低（代码、公开文档）→
              延迟/稳定性要求
              ├─ 高 → 国内中转（低延迟、有发票）
              └─ 低 → 自行接入境外直连
```

**中转 vs 直连的实际差异**，可参考 [AI API 中转 vs 自己翻墙：综合对比](/blog/ai-api-relay-vs-self-vpn/)。

## 六、合同要点：签约前必看条款

无论是直接和海外服务商签还是通过国内代理，合同里几个条款需要重点关注：

**数据处理协议（DPA）**：
- 数据用途（明确禁止用于模型训练）
- 数据存储地理位置
- 数据泄露通知时限（建议 ≤72 小时）
- 合同终止后数据处置方式

**SLA 条款**：
- 服务可用性承诺（99.9% 以上）
- API 限速（rate limit）上限
- 故障响应时间

**计费与账单**：
- 计费周期和账单格式（需财务能对账）
- 超出预付额度后的处理方式（暂停还是继续扣费）
- 退款政策

## 七、推进速度：如何在大公司快速落地

大公司的采购流程往往 3–6 个月，但有几种方法可以加速：

1. **先走"个人 / 小团队试点"**：许多公司有低门槛的小额直采通道（如 1 万元以内由部门负责人审批），先用小额额度跑出数据，再用数据推动正式采购
   
2. **搭上年度预算节点**：大公司通常在 10–11 月做次年预算，这时把 AI 工具预算写进去，次年执行时只需走对账单，不用重新审批

3. **绑定已有合同**：如果公司已有微软、阿里云等大厂合同，AI 工具（Azure OpenAI、通义千问）可以直接挂靠，不用新开供应商

4. **找内部冠军（Champion）**：技术团队推采购很难，找一个关心效率的业务方 VP 联署申请，成功率大幅提升

## 八、常见阻力与应对话术

| 阻力来源 | 典型说法 | 建议应对 |
|---------|---------|---------|
| IT 安全 | "不允许代码上传第三方" | 区分场景：公开代码 vs 私有代码，只用于公开项目或非核心代码 |
| 法务 | "数据出境无法批" | 调整方案为国内大模型或私有化部署，或选国内合规代理商 |
| 财务 | "无法付境外服务" | 推荐支持人民币发票的国内服务商 |
| 管理层 | "ROI 不清晰" | 准备具体数字：节省工时 × 工时单价，对比工具成本 |
