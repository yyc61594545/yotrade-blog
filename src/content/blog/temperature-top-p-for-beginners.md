第一次打开 OpenAI 或 Claude 的 API 文档，很多人会在参数列表里看到 `temperature` 和 `top_p` 这两个词，扫一眼说明——"控制随机性的采样参数"——然后一脸茫然地把它们保持默认，从头到尾没碰过。

这很正常。官方文档默认你已经懂概率论，但大部分人第一次接触这两个参数时，根本不知道它们和"AI 的回答"有什么关系。这篇文章不讲公式，只讲人话：这两个参数到底在干什么、调高调低会发生什么、新手应该怎么下手。

## 一、先建立一个直觉：AI 在"抽签"，不是在"背答案"

AI 生成文字，不是从一个固定答案库里"查找"最佳答案，而是每写一个字（准确说是一个 token），都要做一次抽签。

打个比方：你问 AI"今天天气怎么样"，AI 心里对下一个字有很多候选，每个候选都有一个"可能性"：

| 候选字 | 可能性 |
|---|---|
| 很 | 35% |
| 不 | 28% |
| 有 | 18% |
| 晴 | 12% |
| 其他 | 7% |

如果 AI 每次都选可能性最高的那个字，回答会非常"标准"，但也容易显得死板、千篇一律。如果 AI 每次都是纯随机抽签，回答会天马行空，但也容易语无伦次、答非所问。

`temperature` 和 `top_p` 就是用来控制"这次抽签抽得有多野"的两个旋钮。

## 二、temperature：抽签时的"胆子大小"

`temperature`（温度）决定了 AI 有多愿意偏离"最保险的答案"。

- **temperature 调低（比如 0 到 0.3）**：AI 更倾向于选可能性最高的字，回答稳定、保守，几乎每次问同一个问题答案都差不多。适合需要"标准答案"的场景。
- **temperature 调高（比如 0.7 到 1.2）**：AI 更愿意冒险选一些可能性没那么高的字，回答会更有变化、更"有创意"，但同时也更容易跑偏、说错话。

一个不太精确但很好记的类比：temperature 就像是给 AI 灌了多少酒。0 是滴酒未沾，一板一眼；1 左右微醺，说话开始有点意思；超过 1.5 基本就是喝断片了，说话东拉西扯。

## 三、top_p：只在"靠谱候选"里抽签

`top_p`（也叫 nucleus sampling，核采样）换了一个角度控制随机性：它不直接调"胆子"，而是先划定一个范围——只从**加起来占总可能性 top_p 比例**的候选字里抽签，范围外的字直接被排除，不管 temperature 多高都不会被选中。

还是用上面的例子，如果 `top_p = 0.9`：

1. 把候选字按可能性从高到低排序：很(35%)、不(28%)、有(18%)、晴(12%)、其他(7%)
2. 从高到低累加，直到刚好超过 90%：35% + 28% + 18% + 12% = 93%，够了
3. 只在"很、不、有、晴"这四个字里抽签，"其他"被踢出候选池

`top_p` 调得越低（比如 0.5），候选池越窄，回答越保守；调得越高（接近 1），候选池越接近全部候选，回答空间越大。

## 四、temperature 和 top_p 到底有什么区别

这是新手最容易混淆的地方，一句话说清楚区别：

- **temperature** 改变的是"每个候选字被抽中的概率分布形状"——拉平（更随机）或者拉尖（更确定）。
- **top_p** 改变的是"参与抽签的候选字有哪些"——划定一个范围，范围外的字直接出局。

两者可以同时使用，但**不建议同时大幅调整**。业界惯例是固定一个（通常固定 `top_p = 0.9` 或 `1`），只调另一个（通常调 `temperature`），这样效果更容易预测，不会因为两个变量互相影响而"调了半天不知道是谁的锅"。

原理部分如果你想看更深入的数学推导（比如 `top_k`、`min_p` 怎么参与其中），可以看 [temperature 与 top_p 深度解析](/blog/llm-temperature-top-p-deep-dive/)，这里只讲够用的直觉。

## 五、新手直接照抄的调参建议

不想理解原理、只想知道"该填几"，可以直接抄这张简化表：

| 你在干什么 | temperature 建议值 | 为什么 |
|---|---|---|
| 让 AI 写代码 | 0.2 左右 | 代码错一个字符就跑不通，要稳 |
| 让 AI 回答客观问题（查资料、算数） | 0 到 0.2 | 追求"标准答案"，不需要花样 |
| 让 AI 写日常聊天、客服回复 | 0.4 到 0.6 | 需要自然，但也不能太跳 |
| 让 AI 写文案、脑暴创意 | 0.8 到 1.0 | 需要多样性和意外感 |
| 让 AI 写诗、写小说 | 1.0 以上 | 追求出人意料，容错率高 |

`top_p` 新手直接保持默认的 `0.9` 到 `1` 就行，不需要单独调。等你对 temperature 的手感建立起来之后，再去看更细的按任务类型速查表：[按任务类型设置 LLM temperature 速查表](/blog/llm-temperature-by-task-type/)。

## 六、两个常见误区

**误区一：以为 temperature 调到 0 就能保证结果完全一样。** 大部分厂商在 temperature 为 0 时，回答依然可能有极小的浮动（和模型内部的浮点数计算、并发调度有关），这是正常现象，不代表参数没生效。如果你要做"结构化输出"这类必须精确的任务，更推荐用 JSON Schema 之类的强约束方式，而不是单纯依赖低温度。

**误区二：以为 temperature 越高，AI 就越"聪明"。** 恰恰相反，temperature 只影响"表达的多样性"，不影响 AI 的知识水平和推理能力。调高 temperature 不会让 AI 变得更懂、算得更准，只会让它说话更"跳"，甚至更容易一本正经地编造内容（幻觉现象）。

如果你是通过 API 调用模型（而不是网页版聊天），可以直接在请求里加上这两个参数试试效果：

```json
{
  "model": "claude-sonnet-5",

}
```
