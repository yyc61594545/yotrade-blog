V2EX 上关于 Codex 的提问，最集中的一条是“怎么让 Codex 用上 ChatGPT 网页版的额度”。这个问题本身就建立在一个误解之上：**网页聊天的额度和 Codex 的额度从来不是同一个池子**。搞清这一点，很多“额度不够”的焦虑会自动消失，剩下的才是真正需要决策的部分。

本文依据 OpenAI 公开帮助文档和社区普遍观察整理，具体数字随时可能调整，文中所有额度值都是**近似值，仅作参考**；以你账号设置页里显示的用量为准。

## 一、Codex 额度的三层结构

先建立一个模型。用 ChatGPT 账号登录 Codex 后，你的用量受三层约束：

| 层 | 约束对象 | 窗口 | 备注 |
|---|---|---|---|
| 套餐层 | 你是 Plus、Pro 还是 Business / Enterprise | 按套餐决定上限 | 决定下面两层的容量 |
| 短窗口 | 一段时间内的“消息 / 任务”数 | 约 5 小时滚动 | 最常撞到的一层 |
| 长窗口 | 一周累计用量 | 约 7 天滚动 | Pro 用户跑大任务时才容易撞 |

两个窗口同时生效，任意一个耗尽都会被限速或暂停。CLI 里执行 `/status` 或在 IDE 扩展里查看用量面板，可以看到两个窗口的剩余比例和刷新时间。

关键点：**这三层都属于 Codex，与 ChatGPT 网页聊天的消息上限是分开计数的**。你在网页上聊了一下午，不会消耗 Codex 的额度；反过来 Codex 跑完一堆任务，网页聊天照常可用。

## 二、CLI、IDE 扩展、云端任务：共用还是分开

这是第二个常见误解。用同一个 ChatGPT 账号登录后：

- **Codex CLI**、**IDE 扩展**（VS Code / Cursor 等）、**Codex 云端任务**（网页版 Codex、GitHub 集成）**共用同一份 Codex 额度**。
- 早期云端任务曾有过单独的宽松计算，那是推广期的临时政策，现在已经统一到同一个池子。
- 本地任务和云端任务的“计费权重”不完全相同：一条云端任务通常比一条本地消息消耗更多，因为它包含环境准备、多轮工具调用和完整执行过程。

可复用的判断：**如果你的短窗口经常提前耗尽，先看是不是云端任务占了大头**。把探索性、多轮小改动放在本地 CLI 做，把长时间独立执行的重活丢给云端，通常比全放云端更耐用。

## 三、Plus 和 Pro 差在哪里

用一个常见的近似口径描述：

| 套餐 | 短窗口（约 5 小时） | 周上限 | 典型体感 |
|---|---|---|---|
| Plus | 约几十到一百多条本地消息 | 有 | 每天集中写 1–2 小时代码够用，连续跑大重构会撞墙 |
| Pro | 约 Plus 的 5–10 倍 | 有，明显更高 | 全天使用、并行多个任务基本不会碰到短窗口 |
| Business / Enterprise | 按席位，通常接近 Pro 或可加购 | 管理员可配置 | 团队统一管理 |

几点补充：

1. “一条消息”的消耗不是固定的。上下文越长、工具调用越多、思考等级越高，一条消息的实际扣除越多。思考等级怎么选，可以看 [Codex 思考等级与实际表现的权衡](/blog/codex-thinking-level-tradeoff/)。
2. Plus 的额度是为“个人日常辅助”设计的，不是为“让它整天独立跑”设计的。用 Plus 跑无人值守自动化，额度撞墙是正常现象，不是账号被限。
3. Pro 的溢价是否值得，取决于你是否真的每天用满 Plus。一个简单的方法：连续一周记录你在 Plus 上撞短窗口的次数，一周超过三次再升。Pro 的国内开通方式见 [ChatGPT Pro $200 月卡国内开通教程](/blog/cn-chatgpt-pro-200-dollar-payment/)。

## 四、API Key 登录为什么另算

Codex 支持两种登录：**ChatGPT 账号登录**和 **API Key 登录**。二者的计费完全不同：

```text
ChatGPT 账号登录  → 消耗套餐内 Codex 额度，不额外收费，受上述窗口限制
API Key 登录      → 按 token 付费，走 OpenAI 平台账单，不受套餐窗口限制
```

这意味着：

- 订阅了 Plus，不代表你的 API Key 有免费额度；平台账单是独立的预付费或后付费。
- 用 API Key 登录，Codex 的“额度”就变成了你平台账户的余额和速率限制，没有“5 小时窗口”一说。
- 两种方式在同一台机器上可以切换，但用量不互通，各算各的。

对国内用户还有一个现实差别：ChatGPT 账号登录 Codex 时可能会被要求验证手机号，而 API Key 登录通常没有这一步。这部分站内 [Codex 登录要求验证手机号：国内用户怎么过](/blog/cn-codex-login-phone-verification/) 已经写清楚，这里不展开。

## 五、额度耗尽后的正规选项

短窗口撞墙时，界面会提示重置时间。除了等，还有几种做法：

1. **加购额度**。Plus / Pro 用户在额度用尽后可以按次购买额外用量，价格以账号内页面显示为准。适合偶尔冲刺一次的人，不适合长期依赖。
2. **切到 API Key 登录**接着干。适合手头有平台余额、且当前任务不能停的人。注意切换后模型可用列表和默认设置可能不同。
3. **降低单条消息的消耗**：缩短上下文（新开会话）、把思考等级从 high 调到 medium、减少无意义的“再试一次”。这些在 Plus 上尤其有效。
4. **调整任务分配**：探索和小改动本地做，长任务云端做，避免云端跑十几轮小修小补。

不建议的做法只有一条：**用多个账号轮换**。这既违反使用条款，也是号池和风控问题的根源，后果可以参考 [ChatGPT 共享账号的真实风险与替代方案](/blog/cn-chatgpt-shared-account-risk/)，Codex 号池的问题只会更严重，因为它的每条任务都带着你的代码仓库。

## 六、几个常见误区一次说清

**“我是 Plus，为什么额度显示得比别人少？”**
额度不是固定条数，而是按消耗计算。同样一百条消息，长上下文和高思考等级的人会更早耗尽。

**“网页版 GPT 的额度还有很多，Codex 却没了。”**
正常。两者独立计数，网页的剩余无法转给 Codex。

**“云端任务是不是不算额度？”**
现在算，而且单条消耗通常更高。

**“API Key 登录能用套餐额度吗？”**
不能。API Key 只走平台账单。

**“额度重置是每天固定时间吗？”**
不是，是滚动窗口：从你第一条消息计时，到点后逐步释放，不是整点清零。
