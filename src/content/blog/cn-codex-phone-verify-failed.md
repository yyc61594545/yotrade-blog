Codex 验证手机号失败，最耗时间的不是失败本身，是**在错误的方向上反复试**。号码类型不对却一直重发短信，或者明明是终端超时却跑去换号——这两种都能白白烧掉一下午和几十块钱。

这篇给一套分流方法：先判断卡在哪一层，再做对应的动作。三层互不通用，走错就是白试。

## 一、先分流：三层，选一层

| 你看到的 | 在哪一层 | 处理方向 |
|---|---|---|
| 浏览器没弹出来 / 弹出来是空白页 / 登录的不是你要的账号 | 浏览器层 | 和号码无关，先修环境 |
| 页面提示号码无效、不支持、已被使用 | 号码层 | 换号或换号码类型 |
| 提示尝试次数过多 | 号码层（频率） | 停手等冷却 |
| 页面一直收不到码 | 号码层（投递） | 可重试或换号段 |
| 浏览器里显示成功，终端却报超时 / 卡着不动 | 终端层 | 和号码无关，重新执行命令 |

**最后一行是 Codex 独有的**，别处的教程不会提，而它恰好是国内用户最容易误判的一种：验证明明过了，却以为「号码不行」，于是再买一个号——钱花了，问题还在。

## 二、浏览器层：三种情况

### 浏览器根本没打开

`codex login` 依赖系统默认浏览器。没弹出来的话，终端一般会打印一条 URL，手动复制到浏览器里打开即可。

如果终端什么都没打印，先确认 CLI 装好了：

```bash
codex --version
```

没输出版本号就是安装问题，不是验证问题，回去重装。

### 打开了但页面空白或一直转圈

网络环境问题。授权页要加载多个外部资源，加载不全就会卡住。换个网络环境重开，**在开始验证之前换好**——中途换出口容易被判定异常。

### 登录的账号不是你要的那个

浏览器里如果已经登录了另一个 OpenAI 账号，授权会直接用那个账号。常见于同时有个人号和工作号的人。

处理：用无痕窗口，或者先在浏览器里退出当前账号，再重新执行 `codex login`。

## 三、号码层：按报错措辞分四类

**把界面切成英文**再看报错——中文提示有时会把几种情况合并成一句笼统的「号码有误」，切了英文才分得清。

| 英文提示 | 含义 | 该做什么 | 不该做什么 |
|---|---|---|---|
| `not supported` / `invalid` | 号码类型或地区不被接受 | 换**类型**（比如从 VoIP 换成真实运营商号） | 换写法、加减区号 |
| `already associated with another account` | 这个号在 OpenAI 用过了 | 换一个**同类型的别的号** | 换平台、换类型 |
| `too many attempts` | 触发频率限制 | 停手，等几小时 | 继续点重发 |
| 迟迟收不到码 | 短信通道投递问题 | 等 2~3 分钟再重发一次，仍不行换号段 | 连点重发 |

最容易搞反的是前两行。**「不支持」是这一类号都不行，「已被使用」是这一个号不行**——一个要换类型，一个只要换号码。方向正好相反。

这两种各自的细节，见《[ChatGPT 提示手机号无效或不支持的原因与解决](/blog/cn-chatgpt-phone-number-not-supported/)》和《[提示手机号已被使用或已关联其他账号怎么办](/blog/cn-chatgpt-phone-already-used/)》。

另外，在怀疑号码之前先排掉几个纯格式问题：区号下拉没选、号码里带空格或横杠、重复填了区号、输入法没切英文导致全角数字。这些会报成「必填」或「无效」，但换多少个号都解决不了，逐句解释见《[「电话号码是必填项」怎么办](/blog/cn-chatgpt-phone-required-field/)》。

## 四、终端层：浏览器成功了但登录没成

这是 Codex 特有的坑。`codex login` 跳浏览器之后，终端在等一个回调，**有超时**。

现实中的时间线常常是这样的：敲了 login → 发现要验证手机号 → 去找号、买号、等码 → 十几分钟过去 → 浏览器里验证成功 → 回到终端，发现早就超时退出了。

处理很简单：**把号准备好，再重新执行 `codex login`**。这次验证信息已经在账号上了，流程会快很多。

真正的教训是顺序：号要在敲命令之前就到手，不要一边买号一边让终端等着。这一点在《[Codex 账号怎么开：国内从注册到命令行登录一次走通](/blog/cn-codex-account-cn-guide/)》的清单里排在第一位，就是因为这个。

## 五、重试节奏：什么时候该停

失败之后的动作节奏，比换什么号更影响最终结果：

- **收不到码**：等 2~3 分钟再重发**一次**。还是没有就换号段，别在同一个号上继续。
- **撞到「次数过多」**：这个号短时间内基本废了。等几小时，期间不要用它做任何尝试。
- **同一种失败连续两次**：说明方向对但号源不行，换号源。
- **两种不同类型的失败交替出现**：说明方向不对，回第一节重新分流。
- **累计失败超过四五次**：停下来算账。见下一节。

**最伤的动作是连点重新发送**。它会把你推进频率限制，而频率限制期间即使换了好号也验不了，等于把后面的路也堵上。

## 六、该换方案的临界点

接码平台的账要这么算：单价看着几毛钱，但多数平台**要先充值**（常见 $5~$10 起）。真实支出是充值额，不是单次价。试了七八次没过，这笔钱已经花了，问题还没解决。

所以有个简单的临界点：**当你在接码上的累计支出接近一次性方案的价格，而成功率没有改善迹象时，方向本身就该换了**。继续试通常只是在验证同一个号池。

## 七、过了之后立刻做两件事

1. **把账号恢复方式配全**：恢复邮箱、绑定登录方式。号码是临时的，账号不该只挂在它上面。
2. **记下成功的组合**：哪种方式、哪国号、哪个号段。换设备换网络后可能被要求重新验证，届时直接复用，不必再排查一遍。

第 2 条几乎所有人都会跳过，然后三个月后重走一遍本文。

## 八、一张速查表

| 症状 | 层 | 第一个动作 |
|---|---|---|
| 浏览器没弹 | 浏览器 | 手动复制终端打印的 URL |
| 页面空白 | 浏览器 | 换网络环境重开 |
| 账号不对 | 浏览器 | 无痕窗口重来 |
| 号码无效 / 不支持 | 号码 | 先查格式，再换号码**类型** |
| 已被使用 | 号码 | 换一个同类型的号 |
| 次数过多 | 号码 | 停手等几小时 |
| 收不到码 | 号码 | 等 2~3 分钟重发一次，再不行换号段 |
