填号码，点发送，页面立刻弹出一行红字：`This phone number is not supported`。换一个号，同样的红字；再换一个，还是它。

问题在于，这句话是个**笼统的兜底提示**——OpenAI 在四个完全不同的判断层上都可能返回它。不区分清楚，你就会在换号这件事上反复做无用功：明明是格式填错了，却一直在买新号码。

这篇把这句报错拆开，给出每一类的识别方法和对应动作。和"号码填进去了但验证码不来"是两回事，那种情况见文末相关阅读。

## 一、四层判断，一句报错

OpenAI 对你填进去的号码，依次做四层检查，任何一层不过都可能返回相似的提示：

| 层 | 检查什么 | 典型文案 | 能不能自救 |
|---|---|---|---|
| 1. 格式层 | 号码位数、国家码是否合法 | Invalid phone number | **能**，改填法即可 |
| 2. 国家层 | 号段所属国家是否在支持列表 | This phone number is not supported | 不能，必须换国家 |
| 3. 类型层 | 是不是 VoIP / 虚拟号 | This phone number is not supported | 不能，必须换真实号 |
| 4. 历史层 | 这个号码验证过多少个账号 | used too many times / 仍是 not supported | 不能，必须换号 |

**先判断层级，再决定动作。**判断顺序有个小技巧：第 1 层的报错通常是 `Invalid`，2–4 层通常是 `not supported`。看到 `Invalid` 先别急着换号，九成是自己填错了。

## 二、格式层：最冤枉的一类

这一类不用花一分钱就能解决，但每天都有人栽在上面。

**重复输入国家码。**输入框左边已经是 `+1` 的下拉框，右边又填了 `1` 开头的完整号码，实际提交变成 `+1 1650...`。这是最高频的一个。正确填法：左边选国家，右边**只填国家码之后的部分**。

**保留了分隔符。**`(650) 555-0123` 这种从接码平台复制过来的带括号、空格、连字符的格式，有些页面能自动清洗，有些不能。保险做法是只粘数字。

**粘贴时带了不可见字符。**从网页复制号码，容易顺带复制一个零宽空格或换行。表现是"看着一模一样但就是报无效"。处理方法：粘贴到记事本里再手打一遍。

**选错了国家。**下拉框按国家名排序，United States 和 United Kingdom 挨得近，选错了号码位数就对不上。

判据：**报错里出现 `Invalid` 而不是 `not supported`，先回头检查这四条，别换号。**

## 三、国家层：哪些号段直接出局

中国大陆（+86）号码在这一层被直接拒绝，没有例外，也没有技巧可以绕过。这不是针对 ChatGPT 设置的特例——Google、AWS、Stripe 等海外账号体系有类似的地区策略。

香港、澳门号码的表现随时间波动，有时能过有时不能，不建议押注。

**最稳的是美国号（+1）。**它在所有验证入口——注册、创建 API Key、Codex 登录——的表现都最一致。其他支持国家不是不能用，而是在不同入口的命中率差异更大，尤其是 platform 和 Codex 这两个。

这一层没有自救空间：不在支持列表里，就是不在，换号是唯一动作。

## 四、类型层：VoIP 号为什么一定被拦

这是很多人最想不通的一层：号码明明是美国的 `+1`，为什么还是 not supported？

因为 OpenAI 会查这个号码的 **line type**——它属于移动网络（mobile）、固话（landline）还是网络电话（VoIP）。Google Voice、TextNow、Skype 号这类纯 VoIP 号，在电信数据库里有明确标识，查一次就知道，不需要"识别"什么行为特征。

2026 年的现状：**VoIP 号在 OpenAI 的各个验证入口基本都过不去。**网上那些"Google Voice 亲测可用"的教程，多数是早几年的窗口期留下的，现在照着做只会浪费时间。

能过的三类号码：

- **实体运营商卡**（美国当地 SIM 卡）
- **eSIM**（正规虚拟运营商发行的，带真实号码的数据套餐）
- **接码平台手里的真实运营商号码**（注意：接码平台也分号源，便宜的那批经常是复用过度的号，见下一节）

**怎么提前知道一个号码是什么类型？**有公开的 line type lookup 工具可以查号码归属和类型，买号之前查一下比买完再试便宜。接码平台如果标注了 "real SIM" / "non-VoIP"，通常也更贵一些——这个溢价是有道理的。

## 五、历史层：号码不是新的

即使国家和类型都合格，号码还可能因为"用过太多次"被拒。

同一个号码能验证的 OpenAI 账号数量有限（具体阈值 OpenAI 未公布，各方说法在几个以内，视作近似参考）。接码平台的号码是**共享循环使用**的——你租到的号，之前可能已经被几十个人用来注册过。便宜号段的失败率高，原因主要在这里，不在"平台不行"。

表现有两种：

- 明确报 `used too many times` / `too many accounts` → 确定是这一层
- 仍然报 `not supported` → 无法从文案区分，但如果号码本身是美国真实运营商号，那八成就是历史层

这一层的动作只有一个：**换号，且优先换号源。**在同一家平台的同一个号段里反复换，很可能拿到的是同一批已经被用废的号。

## 七、一张决策图

```text
看报错文案
├─ Invalid phone number
│   └─ 检查：重复国家码？带符号？选错国家？→ 改填法，别换号
└─ not supported / used too many times
    ├─ 是 +86 大陆号 → 无解，换美国号
    ├─ 是 Google Voice / TextNow 等 VoIP → 换真实运营商号
    ├─ 是美国真实号但仍被拒 → 号码用过太多次，换号源
    └─ 换了三个真实美国号都不行
        └─ 回头查网络出口地区是否与号码地区差异过大
```

最后一条容易被忽略：国内 IP 配美国号码，部分风控策略会把验证升级或直接拒绝。号码没问题时，先看网络。
