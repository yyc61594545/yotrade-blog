“共享账号”的通用风险站内已经写过一篇：[ChatGPT 共享账号的真实风险与替代方案](/blog/cn-chatgpt-shared-account-risk/)。本文不重复那些内容，只讲 **Codex 号池特有的部分**。Codex 和网页聊天的本质区别是：它在你的机器上执行命令、读写你的仓库、可以连接你的 GitHub。一个共享的聊天账号泄露的是你问过什么；一个共享的 Codex 账号泄露的可能是你的整个代码库和它能触达的一切。

本文只做机制说明和风险判断，不提供任何绕过限制的方法；文中比例、时间均为社区普遍观察，仅作参考。

## 一、Codex 号池的三种形态

市面上叫“号池”的东西技术上不是一回事，风险也不同：

| 形态 | 你拿到的是什么 | 服务商能看到什么 | 典型话术 |
|---|---|---|---|
| 凭据共享 | 一个账号密码，或一份 `~/.codex/auth.json` | 同账号下所有会话的历史 | “登录后别改密码” |
| 代理注入 | 一个自定义 API 地址 + 一个池方 Key，池方在中间替换成真实账号 | 你发出的每一个请求和返回 | “改个 base_url 就能用” |
| 账号转卖 | 一个“独享”账号，但注册信息不在你手里 | 注册邮箱、恢复手段 | “独享号，永久保修” |

三者里代理注入最隐蔽也最危险，因为它从表面看像是“配置了一个中转”，而实际上你所有的 prompt、工具调用结果、文件内容都完整经过第三方服务器。

## 二、风险一：代码与密钥的暴露面远大于聊天

Codex 的每一轮任务里，模型会读取文件、运行命令、把输出回传。这意味着经过账号或代理的数据包括：

- 你让它打开的源码文件，以及它为了理解上下文主动读取的相邻文件；
- 命令输出，包括你没注意到的 `.env`、配置、日志里的密钥；
- 云端任务里连接的 GitHub 仓库内容和 CI 环境变量。

在凭据共享形态下，池方和同池的其他用户在账号的会话历史里可以看到这些；在代理注入形态下，池方在中间层就能记录全部内容。**只要你的项目里有一个不该外泄的东西，号池就不是省钱问题而是事故问题。**

一个最低限度的自查：在项目根目录跑一下，看看有没有明文密钥会被 Codex 读到。

```bash
# 粗查常见密钥模式（仅示例，不保证完整）
grep -rnE "(sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN (RSA|OPENSSH) PRIVATE KEY)" \
  --exclude-dir=node_modules --exclude-dir=.git . | head
```

如果有命中，无论用不用号池，都应该先处理。

## 三、风险二：额度和体验必然是最差的

Codex 额度按账号计算，双窗口滚动（细节见 [Codex 额度机制详解](/blog/cn-codex-quota-explained/)）。一个账号给几十个人共用，意味着：

- 短窗口几乎常年处在限流边缘，首字延迟大、任务排队；
- 云端任务单条消耗高，一个人批量提交就能把全池打空；
- 池方为了维持可用性会限制每人并发或直接换号，你的会话随时中断。

所以号池用户抱怨的“Codex 变慢降智”通常是结构性的，不是可以排查的问题。排查逻辑见 [Codex 变慢与降智的常见原因排查](/blog/cn-codex-rate-limit-throttling/)，其中第五步就是“发现是号池，停止排查”。

## 四、风险三：账号存续与风控牵连

同一账号从多个国家的出口 IP 同时登录、同时开多个 Codex 会话，是服务端风险评估里最典型的异常模式。后果有三层：

1. **账号被要求补充验证**：比如登录时要求验证手机号。此时池方通常不会把验证码给你，账号对你实际失效。
2. **账号被暂停或封禁**：整池用户同时失去访问，池方“保修”通常是换一个同样来路的号。
3. **牵连你自己的账号**：如果你在同一台机器、同一出口 IP 上既登录过号池账号又登录过自己的账号，风控关联是可能的。这一点社区有零星报告，无法证实比例，但风险存在。

## 五、风险四：合规边界在哪里

分开讲平台条款和法律两层：

**平台条款层**。OpenAI 的使用条款明确要求账号凭据不得共享或转让，账号由注册人个人使用；组织用途应通过 Business / Enterprise 的席位机制实现。号池的三种形态都直接违反这一条，平台有权终止账号且不退款。这不是灰色地带，是明确禁止。

**法律层**。这部分因所在地而异，本文不构成法律意见，只列出需要意识到的点：

- 如果你把公司代码通过号池提交给第三方服务器，可能违反与雇主或客户的保密约定；
- 若代码中涉及用户个人信息，经由不受控的第三方处理，可能触及个人信息保护相关规定；
- 号池经营方本身的合规状态未知，一旦其被处置，用户数据的去向不可控。

可复用的判断线：**个人练习项目用号池，损失的是账号和体验；公司项目用号池，损失的可能是你的工作。**

## 六、还在用号池：止损清单

如果你已经在用，按顺序做：

1. **立即停止在公司或客户项目中使用**，个人项目视密钥暴露情况决定。
2. **轮换所有可能被读到的密钥**：`.env`、CI 变量、云服务凭据、GitHub token。
3. **断开云端任务的 GitHub 授权**：在 GitHub 的 Applications 设置里撤销授权给该账号的 App。
4. **删除本机凭据**：`rm ~/.codex/auth.json`，并检查 `~/.codex/config.toml` 里是否有指向第三方的 `base_url` 或 provider 配置。
5. **不要在同一环境登录自己的账号**，至少换网络出口后再登录。
6. 如果项目里发现了明文密钥，把它当作已泄露处理，不要抱侥幸。
