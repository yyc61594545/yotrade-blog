"浏览器里 ChatGPT 用得挺好，装了官方 Windows 桌面版就打不开了。"——这类问题的求助帖下面，回复区几乎永远是"换个节点试试"。但实际上，**浏览器能用而桌面版不能用，本身就是一条很强的线索**：它基本排除了账号、节点和账号地区的问题，把范围缩到了 Windows 上那几个浏览器不会遇到的环节。

本文不堆砌"重启试试"，而是按症状分流，把 Windows 桌面版独有的两个卡点讲透：**它不读浏览器的代理设置**，以及**从 Microsoft Store 装的应用默认被禁止连本机 127.0.0.1**。这两条能解释掉国内环境下相当大比例的"浏览器行、客户端不行"。

## 一、先分清三种症状，别混着查

三种表现对应完全不同的链路，查错方向只会浪费时间：

| 症状 | 说明什么 | 该查哪里 |
| --- | --- | --- |
| 双击图标没反应 / 闪一下就没了 | 应用进程本身起不来 | 安装完整性、系统版本、缓存目录 |
| 窗口能开，但一直转圈 / 白屏 / 卡在登录 | 进程正常，网络请求出不去 | 代理链路（本文重点） |
| 已经登录进去了，但发消息报错或一直不回 | 链路通了，是请求被拒或额度问题 | 账号状态、用量限额 |

**最容易被误判的是第二种和第三种**。界面能完整渲染、侧栏能看到历史对话，说明网络是通的——这时候再去折腾代理就是白费功夫，该去看账号和额度。反过来，如果连登录页都是空白，那不管你账号多正常，问题都在网络层。

先对着上表确认自己是哪一种，再往下看对应章节。

## 二、桌面版不读浏览器的代理设置（最高命中率）

这是国内用户第一位的原因，而且非常反直觉。

浏览器插件式的代理（各类浏览器扩展）、以及某些客户端的"仅接管浏览器"模式，**只对浏览器生效**。Windows 桌面应用走的是系统层的代理配置（WinINET / WinHTTP 那一套）。所以会出现这种局面：

- 浏览器：流量被扩展接管 → 正常访问
- 桌面版 App：流量按系统设置走 → 直连 → 超时转圈

**验证办法**（不需要任何工具）：打开 Windows 设置里的"网络和 Internet → 代理"，看"手动设置代理"是否开启、地址端口对不对。如果那里是关闭状态，而你的浏览器却能正常访问，基本可以确认就是这个原因。

**对应动作**：在你的代理客户端里把模式从"仅浏览器 / PAC 分流"切到会接管系统的模式（通常叫"系统代理"或"TUN / 虚拟网卡"模式），而不是去 App 里找设置——官方桌面版没有给你填代理地址的地方，它只跟着系统走。

## 三、Store 版应用被 loopback 隔离（第二高命中率）

这一条是 Windows 独有的坑，几乎没人会往这想。

官方 ChatGPT Windows 版通过 **Microsoft Store** 分发（也可以用 `winget install --id 9PLM9XGG6VKS -s msstore` 装）。Store 应用跑在 AppContainer 沙箱里，而 Windows 的网络隔离策略**默认禁止这类应用连接本机回环地址**。你的代理客户端在本地监听的恰恰就是 `127.0.0.1:端口`。

结果就是：系统代理明明设好了、浏览器也正常，但桌面版的请求一到 `127.0.0.1` 就被系统直接丢掉——**不是超时，是根本没发出去**。

先查出应用的包名，再加豁免：

```powershell
# 1. 找到 ChatGPT 的 PackageFamilyName
Get-AppxPackage *ChatGPT* | Select-Object Name, PackageFamilyName

# 2. 用上一步拿到的 PackageFamilyName 加入 loopback 豁免列表
#    （管理员身份运行；把引号里的内容换成你自己查到的）
CheckNetIsolation LoopbackExempt -a -n="<上一步的 PackageFamilyName>"

# 3. 确认已经加进去了
CheckNetIsolation LoopbackExempt -s
```

加完**重启一次应用**再试。需要说明的是，这个豁免机制在微软文档里的定位是调试用途，不是给终端用户的常规配置——所以更干净的替代做法是让代理工作在虚拟网卡（TUN）模式下，让流量在网络层就被接管，压根不经过 `127.0.0.1`，自然绕开了这条限制。

**怎么判断自己中的是这一条而不是第二节那一条**：系统代理已经确认开着、浏览器也好用，但桌面版照样转圈——那就是这一条。两条的表现一模一样，区别只在系统代理那个开关的状态。

## 四、应用本身起不来：对应第一种症状

如果是双击没反应、或者窗口闪一下就消失，网络排查全都没意义，按这个顺序查：

1. **系统版本够不够**。官方要求 Windows 10（x64 或 arm64）build 17763.0 及以上。老机器、精简版系统、长期没更新的 Win10 很可能不达标，这种情况下应用会安装成功但起不来。
2. **走 Store 重装一次**。从 `chatgpt.com/download` 跳转到 Store 的那个官方列表安装。第三方站点打包的"ChatGPT 桌面版"安装包有相当比例是套壳或捆绑，这类装完起不来是常态——而且有账号安全风险，不要用。
3. **清掉本地数据重开**。应用缓存损坏会导致启动即崩。在 Store 应用的"高级选项"里选修复或重置，比手工去翻 `%LOCALAPPDATA%` 目录更安全，也不会漏删。
4. **系统时间对不对**。时间偏差过大会让 TLS 证书校验直接失败，表现可以是启动后立刻退出。打开时间同步、确认时区正确，这一步十秒钟，但能省掉一小时的瞎猜。

## 五、能进去但发不出消息：这里往往不是故障

界面正常、历史对话都在、一发消息就报错或者永远不回——这种情况**优先怀疑账号和额度，而不是网络**。

- **撞了用量上限**。ChatGPT 的限额不是一个数字，而是几个同时在跑的窗口（短窗口 + 周窗口），撞上之后要等多久完全取决于窗口起点。这经常被误读成"客户端坏了"，判断方法见 [ChatGPT 各套餐的 5 小时与每周限额怎么计算](/blog/cn-chatgpt-usage-limit-reset-rules/)。
- **订阅状态掉了**。续费扣款失败会导致账号被降级，某些功能随之不可用。排查流程见 [ChatGPT 自动续费失败怎么办](/blog/cn-chatgpt-recurring-failed-fix/)。
- **出口 IP 在请求中途变了**。分流规则不稳、节点自动切换，会让一次会话里前后两个请求来自不同地区，触发风控。表现就是"刚才还好好的，突然就不行了"。把节点固定下来再试。
- **多设备同时在线**。手机、网页、桌面版同时登录同一个账号在某些情况下会引发异常，见 [AI 账号多设备登录的限制与规避](/blog/cn-ai-account-multi-device-login/)。

## 六、几个几乎肯定无效的操作

这些是求助帖里最常见的建议，但对本文讨论的症状基本没用，优先级可以放到最后：

- **反复换节点**。浏览器既然能用，就说明你至少有一个可用节点。桌面版不行是因为它根本没走那个节点，换一百个也一样。
- **卸载重装（在没查清原因之前）**。代理和 loopback 这两类问题，重装之后一模一样会复现，只是白花十分钟。
- **关掉全部杀毒软件**。企业组策略或防火墙确实可能拦，但那通常表现为明确的连接被拒，而不是转圈；个人机上这条命中率很低。
- **改 hosts 文件**。对本文这些症状没有帮助，还容易留下后患。

## 七、一张排查顺序表

照这个顺序走，大部分情况三步之内能定位：

| 顺序 | 检查项 | 怎么判断 | 命中后怎么办 |
| --- | --- | --- | --- |
| 1 | 症状属于哪一类 | 窗口能不能开、界面有没有渲染 | 按第一节分流 |
| 2 | 系统代理开没开 | 设置 → 网络和 Internet → 代理 | 切到系统代理 / TUN 模式 |
| 3 | 是不是 loopback 被隔离 | 系统代理开着但仍转圈 | 加豁免，或改用 TUN 模式 |
| 4 | 安装来源和系统版本 | 是否 Store 官方包、build ≥ 17763 | 走 Store 重装 |
| 5 | 系统时间 | 时间与时区是否正确 | 开启自动同步 |
| 6 | 账号与额度 | 界面正常但发不出消息 | 查限额和订阅状态 |

**最值得记住的一条判断**：先问自己"界面渲染出来了吗"。渲染出来了，网络就是通的，别再碰代理；没渲染出来，账号再正常也先查网络。这一个问题就能砍掉一半的无效排查。
