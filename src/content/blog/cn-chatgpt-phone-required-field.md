填到最后一步，页面弹出一行红字：**「电话号码是必填项」**（英文界面是 `Phone number is required`）。输入框下面还可能跟着一两句别的提示。很多人第一反应是「这个框能不能跳过」，然后开始试各种填法——填公司座机、填 +86、填一串随机数字，全部被拒。

这篇不讲怎么弄号码（那是另一篇的事），只做一件事：**把这个弹窗里可能出现的每一句话拆开，告诉你它具体在说什么、对应该做什么动作**。因为这几句提示看着都像「号码有问题」，但背后是四种完全不同的情况，走错方向会白花钱。

## 一、先确认是哪一个流程在要号码

同样一句「电话号码是必填项」，在三个地方都会出现，处理优先级完全不同：

| 出现位置 | 触发时机 | 能不能绕开 |
|---|---|---|
| 网页版注册 | 填完邮箱密码后的下一步 | 2026 年多数情况下**不弹**，弹了说明命中了风控或地区策略 |
| Codex / CLI 登录 | `codex login` 跳浏览器授权时 | 基本躲不开，属于这条路的固定门槛 |
| 创建 API Key | platform.openai.com 首次建 key | 躲不开 |
| 账号操作中途 | 换设备、换网络、改密码后 | 属于重新验证，触发条件不公开 |

**先看清楚自己在哪一栏**，因为第一栏有相当概率根本不需要处理——换个干净的浏览器环境重走一遍注册，弹窗可能就不出现了。后面三栏则是硬性要求，再怎么换环境也躲不掉，得老老实实准备一个能收码的号。

关于 Codex 这条路为什么比网页版多一道，以及两种登录方式的差别，见《[Codex 登录要求验证手机号：国内用户怎么过](/blog/cn-codex-login-phone-verification/)》，这里不重复。

## 二、「电话号码是必填项」本身在说什么

这句话是**表单校验**，不是风控判断。它的含义只有一个：这个输入框现在是空的，或者你填的内容没通过格式检查，所以提交按钮不放行。

它**不代表**：

- 你的号码被拒绝了（那是另一句提示）
- 你的账号有问题
- 平台在针对你的地区

实际见过的几种「明明填了还是报必填」的原因：

1. **国家区号下拉框没选**。号码填了，但前面的国旗/区号还停在默认项没动，表单认为这是不完整的输入。
2. **号码里带了空格、横杠或括号**。从别处复制过来的号码常带格式字符，粘进去看着没问题，校验不过。
3. **重复填了区号**。选了 `+1` 之后又在输入框里写 `+1 415…`，等于 `+1 +1 415…`。
4. **粘贴时带了不可见字符**。从微信、网页表格里复制尤其容易。稳妥做法是先粘到记事本里，再手敲一遍。
5. **输入法没切到英文**。全角数字不算数字。

**先把这五条排掉**，再考虑号码本身的问题。这一步不花钱，但能解决相当一部分「卡住」。

## 三、填完之后的第二句提示才是关键

格式过了，点提交，真正有信息量的提示才会出现。下面这几句要分清楚：

| 提示（英文原文） | 中文界面常见说法 | 真实含义 | 对应动作 |
|---|---|---|---|
| `This phone number is not supported` / `Invalid phone number` | 号码无效 / 不支持该号码 | 号码类型或所在地区不在可接受范围 | 换号码类型，不是换写法 |
| `Phone number already associated with another account` | 该号码已被使用 | 号码历史问题，和地区无关 | 必须换一个号，同号再试没用 |
| `Too many attempts, try again later` | 尝试次数过多 | 频率限制 | 停手，等几小时，别连点 |
| `We couldn't send the code` | 发送失败 | 短信通道问题 | 重试或换号段，属于投递层 |
| 下拉框里**找不到中国** | —— | 该地区不在可选范围 | 这一层没得谈，只能换国家 |

最容易被搞混的是第一行和第二行。「不支持」是**类型/地区**问题，说明这一类号码本身不行；「已被使用」是**这个具体号码**的历史问题，换一个同类型的号可能就过了。方向完全相反——前者换号段，后者换号码。

这两种情况各自的细节，分别在《[ChatGPT 提示手机号无效或不支持的原因与解决](/blog/cn-chatgpt-phone-number-not-supported/)》和《[提示手机号已被使用或已关联其他账号怎么办](/blog/cn-chatgpt-phone-already-used/)》里讲过。

## 四、把界面切成英文，提示会更准确

中文界面的提示有时会把几种情况合并成一句笼统的「号码有误」或「请输入有效的电话号码」，你就分不出到底是格式问题还是号码被拒。

切英文的办法：在账号设置里改语言；或者直接在浏览器里用英文环境打开注册页。切完再触发一次，看英文原文落在上表的哪一行。

这不是玄学——**报错措辞的颗粒度是有差别的**，而你要做的判断恰好依赖这个差别。多花三十秒切语言，比盲目试五个号码划算。

## 五、「+86 能不能填」这个问题的准确答案

准确的说法是：**取决于你在哪一个流程、什么时候试**，没有一个永远成立的答案。

有几点可以明确：

- 下拉框里**能不能选到中国**，是第一层判断。选不到，后面都不用试。
- 能选到，也不代表一定能收到码。选得到只说明这个地区没被整体排除。
- 可用范围**会变**。因为某地区号码被大量用于批量注册、通道投递率太低等原因，平台会调整，而且不发公告。

所以唯一可靠的做法是：**自己试一次**。填 +86 号码提交，看落在第三节表格的哪一行。三十秒就有答案，比看任何没标日期的教程都准。

顺带一条判断原则：看到「2026 支持哪些国家」这类标题，先找它是几月写的。找不到日期，就当它不存在。哪些国家可选、怎么自查，见《[OpenAI 手机验证支持哪些国家号码：怎么自查](/blog/cn-openai-phone-verify-country-list/)》。

## 七、几个会让事情变糟的动作

- **连续点「重新发送」**。触发频率限制后，这个号码短时间内基本废了，还要等冷却。
- **一次准备一堆号轮着试**。失败记录会累积，反而更快撞上「尝试次数过多」。
- **中途换网络环境重试**。在同一次验证流程里频繁换出口，容易被判定为异常。要换就在开始之前换好。
- **为了「以后备用」提前囤号**。可用范围会变，今天能用的号段两个月后未必还行，囤号是在赌一个会变的规则。
- **把这个框当成可以跳过的选填项**。写着 required 就是 required，没有前端技巧能绕过服务端校验。

## 八、一个简短的处理顺序

按这个顺序走，不会绕路：

1. 确认自己在哪个流程（第一节的表）。如果是网页版普通注册，先换个干净环境重试一次，看弹窗还在不在。
2. 弹窗还在 → 把界面切英文。
3. 检查区号下拉、空格横杠、重复区号、全角数字这几个格式问题。
4. 提交，看第二句提示落在第三节表格哪一行，照着那一行的动作走。
5. 确认是号码类型/地区问题，才开始考虑弄号，按第六节选一种。
6. 收到码之后，**立刻**把账号的恢复邮箱和登录方式设置好，别让账号的唯一凭据挂在一个临时号码上。

第 6 步很多人会跳过，然后过几个月换设备被要求重新验证时，又回到原点。
