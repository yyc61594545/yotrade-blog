"同一个问题，上周答得很好，这周就敷衍我"——这是论坛上出现频率极高的抱怨，而且几乎每次都伴随一句"是不是官方偷偷把模型降级了"。

降级这件事没人能从外部证实，但在你怀疑它之前，有五六项**你自己就能查、而且确实经常是真凶**的东西。这篇按从常见到少见的顺序排一遍，最后给一套能把"是不是我的错觉"验出来的方法。

## 一、先看推理档位有没有被降下来

现在的 ChatGPT 模型选择器是两层结构：**选模型**，再**选推理投入档位**（effort）。档位从低到高大致是轻量档、中档、高档、超高档，更高的档位只在付费档位里开放。各档位的具体名字随版本改过几次，别背名字，看界面里实际显示的那几项。

两个容易踩的点：

- **新开会话不继承上次的档位**。你上次手动调到高档解决了一个难题，开新会话默认又回到低档，而你以为自己还在高档；
- **自动路由**。低档模型可以在判断问题复杂时自动切到更高的推理档，这个开关在设置里能关。它开着的时候，"这题到底用了哪档"不完全由你决定——它判断失误，你就拿到一个本该深思却草答的回复。

**可操作的结论**：遇到难题，手动把档位顶到你套餐允许的上限，再评价质量。拿低档的输出去质疑模型能力，是在质疑一个你没真正调用过的能力。关于档位怎么按任务复杂度分，可以参考 API 侧的同类思路：[reasoning_effort 参数的任务分级方法](/blog/openai-reasoning-effort-guide/)。

## 二、记忆和自定义指令：最被忽略的污染源

这一项排第二，但它是我见过**最常被忽略、影响又最持久**的原因。

记忆（Memory）和自定义指令会被注入到你**每一次**对话。问题在于：

- 你几个月前随口说的一句偏好，可能至今还在生效。比如某次为了省时间说过"回答简短一点"，之后所有需要长篇推导的问题都被这句话压扁；
- 记忆条目之间会互相打架。"用中文回答"和某条英文技术偏好同时存在时，模型的输出会在两种风格间摇摆；
- 自定义指令里写了角色设定（"你是一个简洁的助手"），它的优先级足够高，能盖掉你当下这条消息里"请详细分析"的要求。

**怎么查**：设置里逐条看记忆列表，删掉过时的；自定义指令整段读一遍，问自己"这段话会不会让模型不敢把答案写长"。然后开一个**临时聊天**（不读写记忆的那种）问同一个问题——如果临时聊天里答得明显好，污染源就定位到了。

## 三、上下文太长，模型在"忘事"

长会话会退化，这不是错觉，但原因不是降级：

| 现象 | 实际原因 |
|---|---|
| 忘了开头定的规则 | 早期内容在超长上下文里的权重被稀释 |
| 自己推翻前面的结论 | 不同轮次的矛盾信息同时在上下文里 |
| 中途换了个话题/换了语言 | 上下文里混进了别的任务的残留 |
| 越聊越慢、越聊越敷衍 | 每轮都要重读全部历史，成本与干扰同步上升 |

**可操作的结论**：一个会话对应一个任务。任务换了就开新会话，把必要的前提**重新贴一遍**（几百字的成本远小于拖着几万字历史）。一个会话超过几十轮还在原地打转，大概率不是模型不行，是这段上下文已经脏了。

## 四、用量配额打满后的隐式降级

各档套餐对高推理档位都有用量上限。用量打满之后，通常不会给你一个醒目的"你没额度了"弹窗，而是**安静地落到更低的档位继续服务**——于是你感觉它"突然变笨了"，时间点还经常是一天里用得最密的那几个小时之后。

判断方法很直接：**换一天的早上**问同一个问题。如果早上正常、晚上变差，基本就是配额。Pro 各档的实际用量差异见[ChatGPT Pro 5x 和 20x 实际用量差多少、怎么选](/blog/cn-chatgpt-pro-5x-vs-20x-usage/)。

## 五、工具调用会把回答变浅

开着联网搜索、文件分析或代码执行的时候，模型的注意力有一部分花在"用工具"上，输出容易变成**对搜索结果的摘抄**，而不是自己的推理。

典型表现：你问一个需要判断的问题，它甩回来一串带引用的罗列，看着扎实，实际上没有回答你的问题。

**可操作的结论**：要推理就把搜索关掉；要时效信息再开。这两件事混在一起做，两边都做不好。

## 六、国内特有：网络质量会伪装成"质量下降"

这一项国外用户很少遇到，国内用户经常撞上，而且表现特别像模型变差：

- **流式输出中途断掉**，你看到一个没写完的答案，以为它"中途放弃了"；
- **请求被重试**，前一次的部分输出和后一次混在一起，读起来就是自我矛盾、逻辑跳跃；
- **长回答超时**，客户端只渲染了前半截。

区分方法：

```
1. 同一个问题，网页端和 App 各问一次
   → 只有一端差 → 客户端或网络问题，不是模型
2. 换一条线路（或换成稳定的住宅 IP）再问一次
   → 变好 → 网络问题
3. 让它输出一段很长的内容（比如"写 2000 字"）
   → 稳定断在差不多的位置 → 链路超时，不是模型偷懒
4. 以上都正常 → 回到第一到第五项继续查
```

线路本身的选择和国内可用性，见[2026 年 ChatGPT 国内能用吗（最新实测）](/blog/cn-chatgpt-cn-available-2026/)。

## 七、也要承认：有时候是提问变了

这条不太好听但值得写。人对模型的提示词是会**随熟练度退化**的——刚开始用的时候写得很细（背景、约束、期望格式、例子），用顺手之后越写越短，最后变成一句"帮我优化下这个"。

模型的输出质量跟输入信息量强相关。你的提问从 300 字退化到 15 字，输出变差是正常的，不是降级。

自查方法：找出几个月前那条"答得特别好"的对话，看看**当时的提问长什么样**。多数人看完会沉默一下。

## 八、一套能自证的对照方法

想从"感觉变差了"走到"确实变差了"，需要控制变量。按这个做：

```
准备：挑 3 个你熟悉、能判断好坏的问题，存成固定文本

对照组设置（每个问题都跑这两条）：
  A. 临时聊天 + 手动顶到最高推理档 + 关闭联网
  B. 你日常的用法（带记忆、默认档位、开着搜索）

比较 A 和 B：
  A 明显好于 B → 问题在你的配置（记忆/档位/工具），按第一、二、五项修
  A 和 B 都差   → 记录下来，隔一天的不同时段再跑一次 A
  A 时好时坏    → 大概率是配额或网络，查第四、六项
  A 一直稳定差  → 这才是"模型本身变了"的合理怀疑，
                  且你现在有可复现的样本可以去反馈
```

**关键是把问题文本固定下来**。凭记忆比较两个月前和今天的体验，比较的是你的心情，不是模型。
